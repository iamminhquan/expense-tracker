# `internal/api` conventions (Gin/JSON side of the migration)

See `CLAUDE.md`'s "Migration in Progress" section for what this package is and why it exists alongside `internal/handlers`.

## Rules

- **Never let a response array field go out as JSON `null`.** `encoding/json` marshals a nil Go slice (`var x []T`, or a struct field left at its zero value) as `null`, not `[]`. Every client-side consumer in `client/` indexes straight into these arrays (`.length`, `.map`, `.filter`) with no null check, matching the pattern this API has used from the start -- so a `null` crashes the page outright rather than rendering an empty list. This isn't theoretical: a browser smoke test caught it crashing the dashboard and transactions pages for every brand-new account (zero data in every array field) before Phase 2 landed. Initialize with `[]T{}` (or build via `make([]T, n)`/`make([]T, 0, n)`, never a bare `var`) anywhere a slice might end up empty -- `buildPieData`, `buildBarSeries`, `monthOptions`, `categoriesListResponse` are the existing examples to match.
- **A refresh/session cookie's `SameSite` must track `SecureCookies`, never a hardcoded `None`.** `SameSite=None` requires `Secure` on every modern browser (Chrome rejects the cookie outright otherwise, regardless of whether the request is actually cross-site) -- and `SecureCookies` is false for local HTTP dev, where a hardcoded `None` silently drops the cookie entirely. That surfaced as *every* hard page reload in local dev bouncing back to `/login` despite a successful login, caught the same way as the nil-slice bug above. `refreshCookieSameSite(secure bool)` in `auth_handlers.go` is the fix and the pattern: `Lax` (no `Secure` needed, fine for the Vite-proxied same-origin-as-the-browser-sees-it dev setup) when `!secure`, `None`+`Secure` (what the genuinely cross-site Vercel-calling-Render production setup needs) when `secure`.
- **Never embed a struct from another package directly in a response unless you've checked it carries the JSON tags you want.** `csvimport.DateFormat`, `NewCategory`, and `RowError` were written for an `html/template` range, not JSON, and carry no tags at all -- embedding them directly serialized as `"Key"`/`"Label"`, `"Name"`/`"Type"`, `"Line"`/`"Message"` instead of this API's camelCase convention, caught by the same browser smoke test as the two bugs above (a React page reading `data.dateFormats[0].label` got `undefined`, not a crash, which is why this one is easier to miss than a hard null-pointer failure). Wrap in a small local DTO (`dateFormatDTO`, `importNewCategoryDTO`, `rowErrorDTO` in `import_handlers.go` are the examples) whenever embedding an external type whose tags you haven't verified.
- **Verify a change like any of the above with a real browser, not just `go test`.** Both bugs above passed the full Go test suite -- `httptest` never goes through a real JSON encoder's null-vs-empty-array distinction the way a browser's `fetch().json()` does, and it never enforces a real browser's cookie policy at all. `TestListTransactionsEmptyAccountHasNoNullArrays` and `TestDashboardEmptyMonthReportsEmpty`'s raw-body checks (in `*_test.go`) now guard the first regression at the Go level, but they exist *because* a browser caught it first, not instead of checking with one.
- **Duplication over sharing with `internal/handlers`, deliberately.** Small helpers (`usernamePattern`, `categorySwatches`, `vietnamLocation`, `sendTimeout`) and whole value-object files (`transaction_query.go` vs. `req_month.go`/`req_filters.go`/`req_paging.go`) are copied rather than extracted into a shared package. This keeps each half of the migration safely additive -- a change here can never break the live Chi app -- at the cost of two copies to keep in sync until Phase 4 deletes one of them. Keep *behavior* identical between a duplicated pair; a fix to one almost always belongs in the other too.
- **Error shape is always `{"error": "message"}`** (`errorResponse` in `auth_handlers.go`), a flat human-readable string, never a structured per-field error list -- the migration plan's locked decision. Revisit only if a real endpoint needs field-level detail a flat string can't carry.
- **Arrays that *can't* go empty don't need the `[]T{}` treatment** -- `make([]T, len(rows))` (transactions, sessions) is never nil regardless of `len(rows)`, since `make` with an explicit length (even 0) always returns a non-nil slice. The rule above is specifically about `var x []T` and zero-value struct fields built up by conditional `append`.
